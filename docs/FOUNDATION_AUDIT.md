## Changes

- Made refactored v0.2 the root development/build entry. Vite bundles only its reachable modules. Removed the obsolete purple-specific root server and copy-build scripts.
- Archived purple HTML/source under `prototypes/purple-local/`; only its HTML asset paths changed to relative references so it can stand alone. JavaScript/CSS are byte-identical to baseline. Nothing executed the archive or accessed existing browser data.
- Preserved the complete original v0.2 source unchanged for comparison. A reproducible verification script checks original Git blob hashes without executing those scripts.
- Added explicit hash router, session factory/fixtures, recorder transition module with injectable clock, existing demo permission rules, route registry, screen modules, shared UI helpers, and one domain-action dispatcher. Bootstrap exposes teardown for listener/timer cleanup.
- Removed global monkey patches and double document/role event registration. Effective screen rendering occurs through a registered view plus centralized existing demo boundaries.
- Added stable record IDs and calendar dates. Calendar lookup derives day contents from record dates, then opens detail by ID. Multiple records on a day remain individually selectable.
- Enforced existing demo role/context rules at action dispatch and recorder transitions. Invalid or repeated recorder actions cannot erase original timing or create duplicate saves. These are technical guards, not new clinical policy.
- Kept onset/end Unknown, manual check-ins, original attribution, provenance, simulated actions, and all existing concept/research journeys.
- Formatted source and split CSS into baseline/refinement files in the same order. Normalized CSS parity verifies unchanged rules/values/cascade, including light/dark and breakpoints; it is not visual browser evidence.
- Added 21 focused domain/DOM regressions and setup/audit/boundary documentation. No production medical or backend functionality added. No publishing performed.

## Untested and remaining risks

- No browser evidence was collected for this refactor. Real-browser core journeys, theme appearance, 320/390px mobile reflow/document overflow, native dialog, keyboard traversal/focus visibility, zoom, screen readers, and physical-device behavior remain untested. DOM tests are not substitutes for those checks.
- Earlier browser claims in the preserved v0.2 README and in-app evidence page are historical baseline claims, not newly executed validation. The source reference is retained unchanged.
- Existing ambiguous caregiver/clinician scopes remain documented in PROTOTYPE_BOUNDARIES.md; the refactor does not choose production access or safeguarding policies.
- Fixed demo dates, charts, symptom choices, navigation candidates, and illustrative states remain intentionally synthetic. The November calendar shows records with November 2026 dates; it is not a new general-purpose calendar.
- Recorder elapsed time uses wall-clock time and clamps negative differences; clock changes can affect the display. It is not a clinical timer.
- Some supporting concepts (for example optional symptom detail and side-effect confirmations) remain shallow simulations rather than full data models. Direct-linking a check-in without a session can still display the original concept wording; guarded actions cannot create or mutate a missing recorder.
- There is no backend security boundary, persistence, clinical validation, or full accessibility claim. The archived app still has its original localStorage limitations if explicitly run separately.
- Recommended next task: obtain a functioning browser preview and complete the documented cross-theme, narrow-layout, native-dialog, and keyboard regression pass before changing product functionality.
